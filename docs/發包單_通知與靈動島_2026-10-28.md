# 發包單：回覆通知與靈動島（2026-10-28，晏辭簽發）

第三批先做可行性驗證，**驗證結果回報後才做 UI**。

## 設計前提（不可違反）

- **不做「角色主動找你」**：不預寫消息、不排程本地通知冒充角色發言、不在背景發起任何新的模型請求。Holt 尊重 AI 目前的非主動性，假主動是昭昭明確否決的設計。
- 通知只做一件事：**使用者已經送出的那一輪**回覆完成時告知。靈動島只反映正在發生的事（生成中、通話中）。
- 沒有伺服器，不接 APNs／FCM 遠端推送，不做 push-to-start。

## 全局鐵律

1. **禁止改動任何靜態 prompt 文本**（tool_prompts.dart、abilityPrompt、工具區敘述）。本單完全不需要碰 prompt。
2. 發送路徑只有一條：`chat_screen_generation.dart:_sendMessageLocked`（文字和圖片共用）。不要再拆第二條。
3. 隱藏標籤清單只有一份：`lib/services/protocol_tags.dart`。通知正文一律經 `VisibleModelOutput.finalOnly` 清洗，不要自己寫正則。
4. 日誌一律 debugPrint，**不得含消息正文、角色名以外的個人內容、key**。
5. 驗收：`flutter analyze --no-pub lib test` 零新增告警 + `flutter test --no-pub` 全綠。真機項標給昭昭。
6. 不確定就標「未真機驗證」，不要編。iOS 原生 API 以 Apple 文件為準，報錯先對簽名。
7. 改檔前備份到 `backups/<日期>_<主題>前/`，完成後在 `docs/handoff.md` 的「## 完成」下加一行，並新建 `docs/map/notifications.md`（格式照 docs/map 其他檔）。

## 現況（已查證）

- iOS：`ios/Runner/ReplyBackgroundBridge.swift` 已有回覆背景續航（`begin`／`progress`／`end`，channel `holt/reply_background`），收尾時 `notifyCompletion()` 會發一則「Holt／回覆已完成」。**但全專案沒有任何地方請求通知權限**，所以這則通知實際上從來不會出現。
- Dart 端：`lib/services/ios_reply_background_task.dart:IosReplyBackgroundTask`，由 `_sendMessageLocked` 在串流開始前 `begin`，結束時 `finish(completed:)`。
- `AppDelegate.swift` 已設 `UNUserNotificationCenter.current().delegate = self`。
- iOS 部署目標 16.4，Bundle ID `com.yanci.holt`。`Info.plist` 的 `UIBackgroundModes` 只有 `fetch`、`processing`，**沒有 `audio`**，所以通話切到背景就會中斷。
- Android：Manifest 已有 `POST_NOTIFICATIONS`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`；已用 `flutter_foreground_task`（保活用，`lib/services/keep_alive_foreground.dart`）。沒有 `flutter_local_notifications`。
- 全域導航：`main.dart` 的 `rootNavigatorKey`；開對話用 `pushNamed('/chat', arguments: conversationId)`。
- 卡片標題規則：`lib/utils/character_display_name.dart:characterCardTitle`（有備註顯示備註，否則本名）。通知和靈動島的角色名一律用它。

## 批次一：回覆完成通知（iOS + Android）

### 1-1 通知內容規則（共用，純 Dart，可單測）
- 新檔 `lib/services/reply_notification_service.dart`。
- 標題：`characterCardTitle(character)`。
- 正文（解鎖可見）：`VisibleModelOutput.finalOnly(reply)`，再去掉 `[sticker:]`、`[transfer:]` 等功能標記（沿用 `TtsService.extractSpeechContent` 前半段的做法，或抽成共用函式），最多 120 字，超過加「…」。清洗後是空的（例如只有表情包）就改成「傳了一張貼圖」之類的中性描述。
- 鎖屏替代文字：`L.pick(en: '{name} replied', zhTW: '{name}回覆你了', zhCN: '{name}回复你了')`。
- 測試：備註／本名切換、標籤剝除、截斷、空正文 fallback、鎖屏文字。

### 1-2 什麼時候發
- 只在 **AI 回覆已成功寫入 SQLite**之後判斷（`_sendMessageLocked` 插入 aiMsg 之後）。失敗、中斷、使用者手動停止都不發。
- 只在 App 不在前台時發（`WidgetsBinding.instance.lifecycleState != AppLifecycleState.resumed`）。在前台時不發，不做 App 內橫幅。
- 側欄開關：`sidebar_feature_settings.dart` 新增「回覆通知」（SharedPreferences，預設開）。關閉時兩個平台都不發。

### 1-3 iOS 實作（走原生，不引入第二個通知插件）
- 原因：`flutter_local_notifications` 也會接管 `UNUserNotificationCenter.delegate`，會跟 AppDelegate 現有設定打架。iOS 繼續用 `ReplyBackgroundBridge`。
- 權限：新增 channel 方法 `requestNotificationPermission`。Dart 在使用者**第一次送出消息時**（前台）呼叫一次，請求 `.alert, .sound, .badge`；拒絕後不再問。設定頁開關從關切到開時再請求一次。
- `end` 方法加參數：`title`、`body`、`placeholder`、`conversationId`。`notifyCompletion` 改成：
  - `content.title = title`，`content.body = body`，`content.threadIdentifier = conversationId`，`userInfo["conversationId"] = conversationId`。
  - **鎖屏只顯示「xx回覆你了」**：iOS 的 `hiddenPreviewsBodyPlaceholder` 是綁在 category 上的，所以每個角色註冊一個 category（`reply.<characterId>`，placeholder = 鎖屏替代文字），發送前合併進 `getNotificationCategories` 現有的集合再 `setNotificationCategories`。系統的「顯示預覽：解鎖時」是 iOS 預設值：鎖屏顯示替代文字，解鎖顯示正文。
  - 不要依賴 `.hiddenPreviewsShowTitle`，鎖屏時標題也會被隱藏，替代文字裡已經帶名字。
- 點通知：在 AppDelegate 的 `userNotificationCenter(_:didReceive:)` 取 `conversationId`，透過 channel 方法 `openConversation` 傳給 Dart；Dart 用 `rootNavigatorKey` 開 `/chat`。如果目前已經在那個對話，就不要重複 push。冷啟動時 Dart 未就緒，要先暫存，等 handler 裝好再補發。
- 進入某個對話時，用 threadIdentifier 清掉該對話已送達的通知。

### 1-4 Android 實作
- 引入 `flutter_local_notifications`，只初始化 Android。
- channel：`holt_reply`，名稱「回覆通知」，importance high。
- 鎖屏隱私：`visibility: NotificationVisibility.private`，`publicVersion` 的內容只有「xx回覆你了」。需要使用者在系統裡開「隱藏敏感內容」才會套用，這點寫進 map 文件。
- Android 13+ 的 `POST_NOTIFICATIONS` 執行期權限，時機和 iOS 相同。
- `groupKey` = conversationId；點擊 payload = conversationId，導航規則同 iOS。
- 背景續航**不在本批範圍**：Android 切到背景後 isolate 通常還能跑一陣子，長回覆被系統殺掉的話，就是不發通知（照實標註，不要用前台服務硬撐）。

### 1-5 驗收（真機）
- 送出後切到別的 App → 回覆完成跳通知；鎖屏時看到「xx回覆你了」，解鎖看到正文；點通知進到正確對話。
- 停在 App 內不跳通知。關掉開關不跳通知。失敗／中斷不跳通知。

## 批次二：靈動島——回覆生成中（iOS）

### 2-0 昭昭要在 Xcode 做的事（附截圖說明寫進 map 文件）
1. File → New → Target → Widget Extension，名稱 `HoltLiveActivity`，勾選 Include Live Activity，不勾 Configuration Intent。
2. 主 App 的 `Info.plist` 加 `NSSupportsLiveActivities = YES`。
3. 新建 `ios/Shared/HoltActivityAttributes.swift`，Target Membership 同時勾 Runner 和 HoltLiveActivity。
4. Extension 的部署目標設 16.4，跟主 App 一致。
- 本批用 App 進程內的 ActivityKit 本地更新，**不需要 App Group、不需要 push token**。

### 2-1 Attributes
```swift
struct HoltActivityAttributes: ActivityAttributes {
  enum Kind: String, Codable { case reply, call }
  public struct ContentState: Codable, Hashable {
    var phase: String          // reply: generating ; call: listening/thinking/speaking
    var receivedCharacters: Int // 只給 reply 用
    var callStartedAt: Date?    // 只給 call 用
  }
  var kind: Kind
  var characterName: String   // characterCardTitle
  var conversationId: String
}
```
- **靈動島上不放回覆正文**（鎖屏也看得到），只放狀態和字數。

### 2-2 生命週期（掛在 ReplyBackgroundBridge）
- `begin`：前台時 `Activity.request`。ActivityKit 只允許前台啟動；App 在前台時系統本來就不會在靈動島顯示自己的活動，所以從一開始就啟動不會閃。
- `progress`：沿用現有 2 秒節流，更新 `receivedCharacters`。
- `end`：成功或失敗都 `end(dismissalPolicy: .immediate)`，成功時由批次一的通知接手。
- 側欄開關「靈動島」（預設開），關閉就不啟動。
- 使用者在系統設定關掉即時動態，或裝置不支援（`ActivityAuthorizationInfo().areActivitiesEnabled == false`）時，靜默跳過，不影響通知。

### 2-3 外觀（主題色從 Dart 傳 accent hex 進 attributes）
- compact leading：角色名的第一個字放在主題色小圓裡。compact trailing：三點輸入動畫。
- expanded：「{name} 正在輸入…」＋「已接收 N 字」。minimal：主題色圓點。
- 鎖屏樣式：同 expanded，背景用半透明主題色。

### 2-4 驗收（真機，iPhone 14 Pro 以上看靈動島，其他機型看鎖屏即時動態）
- 送出後切走 → 靈動島出現並更新字數 → 完成後收起並跳通知。中斷時收起、不跳通知。

## 批次三：通話——背景續航＋靈動島＋Android 常駐通知

### 3-0 可行性驗證（先做，回報後才進 3-1）
- 目前通話切到背景就斷（沒有 `audio` 背景模式）。靈動島通話只在通話能在背景持續時才有意義。
- 驗證項：
  1. `UIBackgroundModes` 加 `audio`，`AVAudioSession` 設 `.playAndRecord` + `.voiceChat`（看 `flutter_soloud`／`speech_to_text`／`audioplayers` 三者誰在設 session，**避免互相覆蓋**）。
  2. 切到背景後 `speech_to_text`（SFSpeechRecognizer）是否還能持續辨識；不能的話，背景期間能否改成只播放、不收音。
  3. 背景中 TTS 能否繼續播放下一句。
  4. Android：`flutter_foreground_task` 加 `foregroundServiceType="microphone"`，背景收音是否正常。
- 回報格式：每項「可以／不行／部分（原因）」，附真機測試步驟。

### 3-1 iOS 通話靈動島（3-0 通過才做）
- 接通時（`_CallPhase.inCall`）啟動 `kind: .call`，`callStartedAt = 接通時間`。計時用 `Text(timerInterval:)` 讓系統自己走秒，**不要每秒推更新**。
- `phase` 在聆聽中／思考中／說話中切換時更新，同一狀態不重複推。
- compact leading：綠色電話圖示。trailing：計時。expanded：名字、狀態、計時；iOS 17+ 用 `LiveActivityIntent` 做掛斷按鈕（`#available` 包住），iOS 16 點擊回到通話頁。
- 掛斷、對方掛斷、斷線一律 `end(.immediate)`。

### 3-2 Android 通話常駐通知
- 通話期間掛前台服務通知：標題是名字，內容是狀態，`usesChronometer` 從接通時間開始走，附「掛斷」action。掛斷後立刻撤掉。

### 3-3 驗收（真機）
- 通話中切到背景：iOS 靈動島顯示計時和狀態，對話能持續（以 3-0 結論為準）；點擊回到通話頁；掛斷後消失。Android 常駐通知同理。
