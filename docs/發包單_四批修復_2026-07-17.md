5. 驗收統一命令：`flutter analyze` 零新增告警 + `flutter test` 全綠。真機項標註給昭昭。
6. 不確定就標「未真機驗證」，不要編。

## 批次一：止血（多燒錢、污染對話、隱私）

零 DB migration、零靜態 prompt 變動。

### 1-1 配置類錯誤不入庫
- 位置：`lib/services/settings/api_settings.dart` buildAdapter 的各 `throw Exception('...未設定')`；`lib/screens/chat_screen.dart` _sendMessageLocked / _sendImageLocked 的 catch。
- 改法：新增 `class ApiConfigException implements Exception`（帶 L.pick 訊息），buildAdapter 全部配置檢查改拋它。chat_screen catch 裡 `on ApiConfigException` 分支：**不插入 assistant 消息**，SnackBar 顯示訊息＋「去設定」action（Navigator 推 /api_settings）。用戶消息保留在庫（已發出的事實不抹）。
- 測試：buildAdapter 各 provider 缺 key 時拋 ApiConfigException。

### 1-2 一般 API 錯誤不再存成角色回覆
- 位置：chat_screen 兩條路徑的 catch（text path ~3070，image path 同型）。
- 改法：移除「出錯了：$e」插入 messages 表的邏輯。改為：SnackBar/頁內錯誤條顯示錯誤摘要＋「重試」按鈕（重試＝用原 outboundText 重走 _sendMessageLocked，用戶消息已在庫，不重複插入——需加 skipInsert 參數或等價機制）。
- 注意：**半段流式文字的保存屬於批次二 2-8**，本項只管「錯誤文本不入庫」。rawReply 暫時照舊丟棄，別在這批搶跑。
- 測試：模擬 adapter 拋錯，斷言 messages 表無新增 assistant 行、_isGenerating 復位。

### 1-3 image path 的 search_chat 殘留清理
- 位置：chat_screen image path（_sendImageLocked 收尾）。
- 根因：image path 調 MemoryActions.processReply 會記錄 `<search_chat>` query，但只有 text path 消費並 clearSearchQuery(2765/2876)，殘留 query 會在下一條文字消息誤觸發二次生成。
- 改法：image path 的生成流程結束處（成功與 catch 都要走到，放 finally）無條件 `MemoryActions.clearSearchQuery(widget.conversationId)`。**不要**在 image path 實作 two-pass——維持「圖片路徑不支援檢索」的現狀，只堵殘留。
- 測試：memory_actions 記錄 query 後模擬 image path 收尾，斷言 lastSearchQueryFor 為 null。

### 1-4 KeepAlive 回前台先 reload prefs 錨點
- 位置：`lib/services/keep_alive_service.dart` onAppResumed。
- 根因：backgroundTick 在獨立 isolate 寫 `keepalive_last_request_at`，主 isolate 內存 `_lastRequestAt` 讀不到，回前台按舊錨點判斷會多燒一針。
- 改法：onAppResumed 開頭 `await prefs.reload()`，讀 prefs 錨點與內存錨點**取較新者**再做窗口判斷。startTime 同理比對。
- 測試：偽造 prefs 錨點比內存新，斷言採用 prefs 值。

### 1-5 備份日誌隱私（本批最高優先）
- 位置：`lib/services/backup_service.dart` :610、:618。
- 改法：610 行 **刪除 `${message['text']}`**，整句改 `debugPrint('Backup import: dropped orphan message id=${message['id']}')`；618 行 print→debugPrint。
- 政策（昭昭已拍板）：孤兒消息**照丟，但要告知**——_importFromJsonUnlocked 的返回摘要 parts 追加「捨棄N條孤兒訊息」（N>0 時）。
- 測試：修那條現在失敗的孤兒測試——改為斷言「丟棄＋摘要含計數＋日誌不含正文」的新政策。65+1 全綠。

## 批次二：緩存與串流生命週期（風險集中，單獨批）

### 2-1 conversation session lease
- KeepAlive 改 lease 制：每個保活窗口持 lease token（conversationId+generation）。刪對話（首頁入口）、備份還原前、新窗初始化失敗回滾——三處必須先 `stop()` 並吊銷 lease。backgroundTick ping 前驗 lease 仍有效（prefs 裡 conv 是否仍存在可延後到 2-2 一併查）。
### 2-2 刪除/切換/還原時取消舊 lease
- home_screen 刪對話、backup_service import 入口（transaction 前）、chat_screen bootstrap 失敗路徑，三處接 stop。還原成功後 KeepAliveService 狀態全清（prefs keepalive_* 全刪）。
### 2-3 usage 去全域化
- 六服務的 static lastCacheStats/lastUsage 改為**隨請求返回**（sendMessageStream 完成時回調或返回 usage 物件；sendMessage 返回值帶 usage）。TokenTracker.recordRealUsage 改收參數，不再讀 static。qwen、openai_compatible 補記錄。診斷面板讀取處同步遷移，internal 標記邏輯保留。
### 2-4 串流 idle timeout
- 六服務 `response.stream` 加 `.timeout(Duration(seconds: 60), onTimeout: (sink) => sink.close())`（或拋自定義 StreamStallException 走錯誤路徑）。local_model 已有的不動。
### 2-5 可取消的 HTTP stream
- adapter 接口加 cancel：服務持有 client 引用，chat_screen _invalidateGenerationState 時調 adapter.cancelActive() → client.close() 強拆連接。注意 finally close 不得雙重 close 拋錯（close 冪等包裝）。
### 2-6 EOF buffer flush
- 六服務 await-for 結束後，殘留 buffer 非空時按同款行解析邏輯補跑一次（含 usage 抓取）。
### 2-7 malformed UTF-8 容錯＋診斷
- 六服務 `utf8.decoder` → `const Utf8Decoder(allowMalformed: true)`；同時 per-request 統計替換發生次數，進 requestDiagnostics（openrouter 進 lastCacheDiagnostics 同位置，其他服務進各自 usage/診斷 map）。
### 2-8 半段回覆 incomplete 保存
- DB migration **v35**：messages 加 `status TEXT DEFAULT ''`（''=正常，'incomplete'=中斷）。流中斷時：rawReply 非空→走標籤剝離（stripReply 路徑，**不執行落庫類標籤動作**）→ 以 status='incomplete' 入庫；UI 氣泡顯示「回覆中斷」角標＋重試。
- **組 history 規則（防炸緩存，想清楚再寫）**：incomplete 消息**照常進 history**（它已是前綴的一部分，跳過會令前綴突變）。只在 UI 標記，不在內容上加任何後綴。
- onCreate 同步加欄；backup appTables 列不用動（同表新欄，export 自動含）。
