# 新記憶寫入去重防護實作報告

日期：2026-08-06  
範圍：對話模型 `<memo>`、摘要模型抽取、記憶頁手動新增，以及待確認提案的處理流程。

## 1. 完成結果

所有「新增一條記憶」的主要入口現在共用同一個本地守門器，寫入前會讀取同角色、同模式下的全部有效記憶，並分成三種結果：

1. **明確重複**：不寫入候選條目，保留原記憶。
2. **疑似重複**：候選條目不先寫入記憶庫，只建立一筆待確認提案。
3. **真正的新記憶**：直接寫入。

判定、建立提案與正式寫入都包在同一個 SQLite transaction 內。即使兩個來源同時提交相同內容，也只會有一條成功寫入，另一條會在交易內重新看見它並被擋下。

## 2. 實際接入的入口

| 入口 | 修改後行為 |
| --- | --- |
| 對話模型 `<memo>` | 先經守門器；明確重複顯示「已略過」，疑似重複建立提案並綁定該則回覆的 Memory 提醒。 |
| 摘要模型記憶抽取 | 每條候選記憶逐條經守門器；不再依靠摘要模型自己判斷是否重複。 |
| 記憶頁手動新增 | 先經守門器；疑似重複時自動切到待確認提案頁。 |

摘要模型原有的近期記憶提示仍可協助它產生較乾淨的結果，但現在只是第一層提示；最終是否寫入由本地守門器決定，而且會比較完整的有效記憶集合，不受提示窗口數量限制。

## 3. 本地判定邏輯

### 3.1 正規化

- 忽略 App 自動加在正文最前方的 `[M/D]` 或 `[YYYY-M-D]` 日期標籤。
- 統一英文大小寫與全形／半形英數字。
- 比較時忽略空白與標點，但保留文字與數字本身。
- 觸發詞以逗號、頓號拆分後比較交集。
- 分類會統一常見的繁中、簡中與英文名稱，例如「重要事件／Important Event」。

### 3.2 分數

綜合分數由以下三部分組成：

- 正文相似度：70%
- 觸發詞重合度：20%
- 分類相容度：10%

正文相似度同時計算字串編輯距離、包含關係與二元字組 Dice 相似度，取其中最高值。這讓小幅改寫可以被抓到，但不需要向量模型。

### 3.3 分流門檻

- 綜合分數低於 `0.68`，且正文相似度低於 `0.76`：視為新記憶。
- 達到上述任一門檻：至少視為疑似重複，送使用者確認。
- 只有在**同分類、無衝突、永久屬性一致**，且正文幾乎一致時，才會判為明確重複並自動略過。
- 明確重複的高相似路徑要求正文至少 `0.94`；較短的直接路徑要求正文至少 `0.97`。完全正規化後一致則可直接判定。

這裡刻意讓「疑似」範圍比「自動略過」範圍寬，避免把有連續性的新狀態誤刪。

### 3.4 衝突保護

以下差異會禁止自動略過，至少進入提案：

- 否定語意改變，例如「會」與「不會」、「有」與「沒有」。
- 狀態轉折，例如開始、停止、恢復、分開、和好、改成。
- 數字或日期不同，例如 2 顆與 3 顆、8 月 10 日與 8 月 12 日。
- 永久記憶屬性不同。

因此相似度很高不等於可以靜默丟棄；時間、數量、承諾和狀態反轉優先保留給使用者判斷。

## 4. 待確認提案 UI

疑似重複會顯示：

- 原有記憶
- 新候選記憶
- 本地重複分數與最多三個判定理由
- 可編輯的合併預覽

提供四個動作：

1. **保留舊條**：拒絕候選，不新增、不修改舊記憶。
2. **使用新條**：確認後才新增新版並歸檔舊版。
3. **合併**：先讓使用者編輯分類、正文和觸發詞，再原子性地建立合併結果並歸檔舊版。
4. **稍後**：保留提案，不碰記憶資料。

「保留舊條」是視覺上的安全預設；會改動資料的動作使用次一級按鈕，主要操作高度至少 44 px。這沿用現有介面樣式，沒有另造一套突兀的視覺語言。

## 5. 資料安全

- 候選記憶在使用者確認前只存在提案 payload，不會混入正常記憶檢索。
- 使用新條或合併時，舊記憶不是硬刪除，而是寫入 archive 後改為 deleted。
- 舊記憶已存在的蛛網連線會轉接到新條目，再移除舊連線。
- 舊條若為永久記憶，新條或合併結果會繼承永久屬性，不能藉由替換意外解除保護。
- 提案建立時記錄舊條版本；若等待期間舊條已改變，提案會變 stale，不會套用過期決定。
- 套用前再比較其餘全部有效記憶；若等待期間出現另一條相似記憶，提案會變 stale，避免再次製造重複。
- 使用者選擇「保留舊條」後，同一候選對同一版本不會反覆生成同一提案。

## 6. Cache、API 與用量影響

此功能完全在本地資料庫寫入階段執行：

- 不修改 System Context。
- 不修改 user message。
- 不增加聊天請求的 content block。
- 不呼叫摘要模型、向量模型或任何額外 API。
- 不刷新、不截斷現有 prompt cache。
- 額外成本只有一次本地 SQLite 查詢與字串比較，token 成本為 0。

摘要模型本身仍照原本流程呼叫；本次只是把它產生的候選結果送入本地守門器，不改其 cache channel。

## 7. 舊記憶的處理範圍

本次守門器會讓**每一條新候選**與全部既有有效記憶比較，所以舊記憶立即成為比對基準，不需要先向量化或遷移資料。

本次沒有主動把「舊記憶彼此之間」全部掃成提案，避免升級後突然出現大量待確認項目，也避免未經確認批次改寫使用者的歷史資料。既有自我註記的完全一致／高相似清理仍由先前完成的自我註記去重機制處理；一般舊記憶的批次整理可另做為可預覽、可取消的維護工作。

## 8. 相容性與備份

- 沿用既有 `pending_memory_actions` 提案表，新增 `create` action 與 payload 欄位，不需要升級資料庫 schema。
- 現有備份已包含記憶與待確認提案資料，因此不需要額外改備份格式。
- 舊版提案沒有新增欄位時仍可照原本 delete／merge 流程讀取。
- 判定理由以語系中立代碼存放，顯示時再依 App UI 語言轉為英文、繁中或簡中，切換語言不會留下混語提案。

## 9. 主要修改檔案

- `lib/services/memory_duplicate_detector.dart`：本地相似度、門檻與衝突判定。
- `lib/services/memory_guard_service.dart`：統一寫入閘門、提案建立、並行與 stale 防護、替換／合併交易。
- `lib/models/memory_action_proposal.dart`：新增 create 提案及候選／分數／理由讀取。
- `lib/services/memory_actions.dart`：對話模型 `<memo>` 接入。
- `lib/memory/summarizer.dart`：摘要模型抽取接入。
- `lib/screens/memory_screen.dart`：手動新增接入與結果提示。
- `lib/widgets/memory_review_tab.dart`：疑似重複提案的比較與決策 UI。
