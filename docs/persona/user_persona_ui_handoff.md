# 使用者多角色 UI 交接清單

狀態：資料與執行邏輯已完成，本文件只界定 UI 要呈現與尚待決策的內容，不預設視覺風格。

## 已固定的產品行為

- 一個使用者可建立多個「自身角色」。既有「我的 Profile」是不可封存的預設角色。
- 每個綁定 scope 是「夥伴 × 日常/RP × continuity」，一個 scope 只綁一個自身角色。
- 修改綁定只影響之後建立的新窗口。已存在的窗口永遠保留建立當下的文字身分。
- 切換夥伴或日常/RP 時，首頁顯示該 scope 將採用的自身角色名稱與頭像。
- 封存自身角色會解除它的所有未來綁定，不刪除舊窗口，也不改寫舊 Prompt。
- 找不到有效綁定時，自動使用預設角色。

## 明天需要提供的 UI 決策

1. **入口位置**：多角色管理放在「我的 Profile」、角色人設卡，或兩處都提供入口。
2. **主要瀏覽方式**：以自身角色清單為主，或先進夥伴再設定日常/RP 綁定。
3. **continuity 呈現**：目前資料支援多條故事線；需決定第一版顯示完整故事線選擇，或先只顯示 `main`。
4. **新增／編輯欄位**：名稱、稱謂、自介、頭像與額外人設文字如何分組；額外人設文字是否收進「進階」。
5. **保存方式**：明確的「儲存」按鈕，或離開欄位即自動保存。綁定建議明確確認，避免誤切。
6. **狀態文案**：需決定「目前綁定」「預設」「已封存」「只影響新窗口」的三語最終用詞。
7. **封存管理**：封存入口、確認框內容、封存角色的恢復入口。
8. **頭像規則**：裁切比例、無頭像占位、是否允許移除，以及舊窗口是否顯示目前頭像。現在邏輯採「舊窗口文字固定、頭像跟隨 persona 現況」。

## 畫面至少要覆蓋的狀態

- 無自建角色，只有預設角色。
- 多個啟用中角色；長名稱、長自介與缺少頭像。
- 日常與 RP 綁定不同角色。
- 同一模式的不同 continuity 綁定不同角色。
- 已封存角色與恢復操作。
- 儲存中、儲存失敗、資料載入失敗。
- 切換綁定時，清楚但不阻斷地提示「只會套用到新窗口」。
- 三語、系統大字級、螢幕閱讀器標籤與至少 48dp 可點擊區域；狀態不可只靠顏色區分。

## 建議交付給實作的素材

- 入口與返回路徑的一張流程草圖。
- 角色清單、編輯頁、綁定頁各一張線框圖。
- 每個操作是即時生效或按下儲存後生效的標記。
- 三語文案；若先給繁中，我可以依既有語氣補齊簡中與英文。
- 顏色、圓角與動畫可沿用現有主題 token；若有特別偏好，再補參考畫面即可。
