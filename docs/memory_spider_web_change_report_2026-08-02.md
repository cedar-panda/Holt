## 舊資料兼容

本次沒有提高資料庫版本、沒有重寫 `memories`、沒有新增必須備份的關鍵表。層級、蛛網分組與容量是由既有 active 記憶和 `spider_web_links` 在讀取時確定性推導：

1. 同模式的既有連線形成關聯組。
2. 關聯組以 20 個節點為一張小蛛網延伸。
3. 未連線記憶依模式與類別分組，以 50 個節點為一張大蛛網延伸。
4. 每層最多 50 個節點與 4 張網；超出時建立下一層。
5. 跨模式或跨層的既有邊不刪除，以跨層關係計數保留。

因此降級到舊版本時，舊版本仍可讀取原記憶和原連線；新分層不會污染備份格式。

## 模型請求與 Cache

手動關聯分析是獨立 API 請求，使用摘要模型設定，但不經聊天的 `StructuredPrompt`、不寫聊天消息、不修改對話歷史，也不移動聊天 rolling cache breakpoint。它只在使用者按下「分析關聯」後發生，因此沒有背景幽靈消費。

該請求的 system context 是：

```text
You organize an existing long-term memory graph. Analyze only the supplied memories.
Return strict JSON and no prose:
{"relations":[{"main_id":1,"related_id":2,"score":0.97,"type":"same_event"}]}

Rules:
- Link only memories that clearly describe the same event, entity, preference, promise, or continuing fact.
- score must be 0..1. Omit anything below 0.92.
- main_id is the broader or more durable memory; related_id is the narrower memory.
- Never suggest deletion, rewriting, or merging. Never invent an id.
- If there is no strong relation, return {"relations":[]}.
```

User message 只包含本次明確選取的記憶 JSON（ID、模式、類別、內容、觸發詞、觸發次數、永久標記）。回覆經本地白名單、閾值、自環、重複、角色與 active 狀態驗證後，才能建立連線。
